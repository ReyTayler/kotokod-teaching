# Прикрепление файлов к документу — план работ

Дата: 2026-08-12
Спека: `docs/superpowers/specs/2026-08-12-knowledge-file-attachments-design.md`

Порядок шагов подчинён одному правилу: сначала то, на что опирается остальное,
и каждый шаг оставляет проект в рабочем состоянии. После каждого — прогон
тестов приложения, в конце — полный `pytest`, typecheck и сборка.

## Шаги

### 1. Общий слой хранения (`storage.py`)

Вынести из `images.py` приём файла: потоковый sha256, временный файл, проверка
лимита, перенос на постоянное место, шардирование пути. Проверка содержимого
становится параметром.

`images.py` переводится на новый слой и продолжает проверять через Pillow.
Поведение картинок не меняется — это чистый рефакторинг, ловится существующими
тестами `test_images.py`.

### 2. Проверка содержимого файла (`file_types.py`)

Белый список: расширение И сигнатура. PDF, OOXML и OpenDocument (сигнатура zip),
старые форматы Office (сигнатура OLE), RTF, zip, txt/csv (по расширению —
сигнатуры не существует).

Формы с макросами (`.docm`, `.xlsm`, `.pptm`) в список не входят.

Тесты — на этом шаге, до всякого API: подменённое расширение, подменённое
содержимое, пустой файл, файл с сигнатурой посреди мусора.

### 3. Модель и миграция

`KnowledgeFile` и `KnowledgeFileUsage`. Отдельные таблицы, не общие с
картинками. Настройка `KNOWLEDGE_MAX_FILE_BYTES = 25 МБ`.

### 4. Белый список узла

`knowledgeFile` в `ALLOWED_NODES`, `ALLOWED_FILE_ATTRS`, проверки типов и
границ. Тест синхронности списков подхватит узел сам.

### 5. Слой данных и сервисы

Функции репозитория по образцу картинок: поиск по хешу, видимость по
использованиям, пересборка связей, поиск осиротевших.

В `update_document` связи файлов пересобираются рядом со связями картинок и по
тому же правилу: сверка наборов в памяти, запрос только при изменении.

### 6. API

`POST /files` — загрузка, только admin. `GET /files/<id>` — скачивание с
принудительным `attachment`, `nosniff` и именем по RFC 5987.

### 7. Уборка осиротевших

Задача-близнец существующей уборки картинок, та же отсрочка.

### 8. Фронтенд

Расширение редактора (атомарный блок), карточка файла, отрисовка в читалке,
кнопка в панели, пункт slash-меню, перетаскивание, загрузка с полосой
прогресса через `XMLHttpRequest`, стили из токенов.

### 9. nginx

Точная локация на загрузку с `client_max_body_size 26m`; регулярная на
скачивание с зоной `api_media`. Порядок: точная → регулярная → префикс `/api/`.

## Итог реализации 2026-08-12

Все девять шагов выполнены. Тестов в разделе — 153 (было 119): 23 на проверку
содержимого файла, 11 на API файлов.

Отклонение от спеки, сделанное сознательно: загрузка с полосой прогресса
(`apiUploadWithProgress`) живёт в `lib/api.ts`, а не в разделе базы знаний.
Спека предлагала держать её рядом с загрузкой файлов, но тогда пришлось бы
вынести наружу выдачу CSRF-токена и обновление access-токена — то есть
размазать аутентификацию по приложению ради одной формы. Функция стоит рядом с
`apiUpload`, своим прямым родственником.

Уборка осиротевших файлов стоит в расписании на 4:35 — через пять минут
после уборки картинок, чтобы две дисковые задачи не толкались на двух ядрах.

Не сделано:

- **Браузером не проверено ничего.** Перетаскивание файла на лист, полоса
  прогресса, замена временного блока настоящим, скачивание с кириллическим
  именем — всё это проверялось только тестами.
