# «Мои уроки» в кабинете преподавателя — история по месяцам

Дата: 2026-09-16
Статус: утверждён пользователем, к реализации

## Задача

Раздел «Мои уроки» кабинета преподавателя сейчас показывает только занятия на
сегодня и служит входом в запись урока. Меняем назначение: история проведённых
преподавателем уроков с переключением по месяцам и детализацией, кто из
учеников был и кто не был.

## Решения пользователя

- Экран **целиком заменяется историей**. Сегодняшних занятий и формы записи урока
  здесь больше нет — записывать урок преподаватель будет из «Календаря».
- Строка урока **свёрнута** и раскрывается по клику, показывая учеников.
- **Сгоревшие занятия показываются** с пометкой: список уроков за месяц совпадает
  со списком «Зарплаты» строка в строку.

## Экран

Шапка — как у «Зарплаты»: заголовок «Мои уроки», стрелки месяцев (вперёд дальше
текущего месяца не пускает), кнопка «Текущий месяц», индикатор обновления.

Список — уроки выбранного месяца по убыванию даты занятия (тай-брейк — id урока).

Свёрнутая строка оформлена как строка «Зарплаты»: дата «дд.мм» и день недели,
название группы с цветом направления, бейдж типа (замена, перенос, доп.занятие,
сгоревшее занятие; у обычного урока бейджа нет) и строка посещаемости.
Денег в строке нет — это не зарплата. Справа — шеврон раскрытия.

Строка посещаемости считается по ученикам урока, а не по строке зарплаты:
«пришли N из M», где N — был или был бесплатно, M — все ученики урока, кроме
«не посещает». У сгорания вместо счётчика — «пропуск сгорел».

Раскрытая строка — ученики урока по алфавиту с пометкой:

| Статус | Когда | Подпись |
|---|---|---|
| `present` | был, не бесплатно | был |
| `free` | был, бесплатное занятие | был, бесплатно |
| `absent` | не был | не был |
| `skip` | неоплачиваемый пропуск | не посещает |
| `burned` | урок-сгорание | пропуск сгорел |

У сгорания посещение в базе технически отмечено «был», но занятия не было —
поэтому статус определяется типом урока раньше флагов посещения.

Пустой месяц — «В этом месяце проведённых уроков нет». Ошибка загрузки —
явное сообщение, не пустой список.

## Бэкенд

Используется существующий `GET /api/lessons` (`MyLessonsView`): скоуп по
преподавателю из токена, фильтры `from`/`to`, порядок `-lesson_date, -id` уже есть.

Добавляется одно поле в `MyLessonSerializer`:

```
students: [{ id: number, name: string, status: 'present'|'free'|'absent'|'skip'|'burned' }]
```

Ученики — по алфавиту. Посещения подгружаются одним `prefetch_related` на всю
выдачу, без запроса на урок. Контракт остальных полей не меняется.

Фронт просит месяц одним запросом: `from`/`to` — первый и последний день месяца,
`page_size=500`. Если `total` больше пришедших строк, экран говорит, что показаны
не все уроки, а не обрезает список молча.

## Отбор уроков и совпадение с «Зарплатой»

История отбирает уроки по преподавателю урока (`lessons.teacher_id`), «Зарплата» —
по преподавателю строки зарплаты (`payroll.teacher_id`). Замер на dev-БД
2026-09-16: из 12 365 уроков ни одного без строки зарплаты и ни одного с
расхождением преподавателей; все 35 сгораний совпадают. Списки идентичны.
Совпадение закрепляется тестом, а не завязкой истории на модуль зарплаты.

## Попутная уборка

- Подписи типов урока, форматирование даты «дд.мм» и шапка с переключателем
  месяцев сейчас живут внутри `PayrollPage`. Выносятся в общие места и
  используются обоими экранами — третьей копии не заводим.
- Из «Моих уроков» уходят форма записи урока, модалка доп.урока и выборка
  сегодняшних занятий. Все эти компоненты продолжают жить в «Календаре».
- CSS-классы `.ml-page` и `.ml-subtitle` остаются без потребителей и удаляются.

## Тесты

- статусы учеников для всех пяти случаев;
- ученики по алфавиту, у урока с несколькими учениками — все ученики;
- чужие уроки не видны;
- фильтр месяца и порядок `-lesson_date, -id`;
- список уроков месяца совпадает со списком `my_payroll_month`;
- число SQL-запросов не растёт с числом уроков.

## За рамками

Правка отметок проведённого урока, фильтр по группе, выгрузка.
