# Прикрепление файлов к документу базы знаний

Дата: 2026-08-12
Раздел: `journal_django/apps/knowledge/`
Состояние: спека утверждена, реализация не начата.

## Задача

К документу базы знаний нужно прикреплять файлы: шаблон договора рядом с
абзацем про договор, презентацию рядом с описанием урока, архив материалов
курса. Сейчас в документ можно вставить только картинку.

## Границы

**В объёме:** загрузка, хранение, отдача, права, уборка осиротевших файлов,
блок в редакторе и в читалке.

**Вне объёма и почему:**

- **Видео.** Другая задача целиком: потоковая отдача с диапазонами байт, правка
  `media-src` в политике безопасности, десятки мегабайт на файл. Смешивать с
  файлами нельзя — получится механизм, который плохо делает и то, и другое.
- **Предпросмотр PDF в окне.** Прямо противоречит решению отдавать файлы только
  на скачивание (см. «Безопасность»).
- **Антивирусная проверка.** Обоснование отказа и остаточный риск — ниже.
- **Замена файла на месте и история его версий.** Замена = удалить блок и
  вставить новый; отдельного механизма не заводим.

## Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Предельный размер | **25 МБ** | Хватает на методичку с картинками, презентацию, скан договора. Диск и канал VPS не страдают, nginx настраивается одной строкой |
| Типы | **Документы и архивы** | PDF, Word, Excel, PowerPoint, OpenDocument, RTF, txt/csv, zip. Покрывает реальные материалы школы. Исполняемое, скрипты и HTML не проходят |
| Размещение | **Блоком в тексте** | Файл стоит там, где о нём речь. Переиспользует ручку блока, slash-меню и всю машинерию блоков вместо нового экрана и нового API |

Отдельное решение по формам с макросами: **`.docm`, `.xlsm`, `.pptm` в белый
список не входят.** Это те же документы Office, но со встроенным исполняемым
кодом; разрешать их — значит раздавать через справочник то, что запускается.

## Как это выглядит

### Вставка

Три пути, одинаковые с картинками:

1. кнопка-скрепка в панели форматирования;
2. `/файл` в slash-меню;
3. перетаскивание файла на лист.

Третий путь требует правки существующего обработчика: сейчас он пропускает
всё, кроме картинок (`imageFiles` в `DocumentEditor.tsx` фильтрует по
`type.startsWith('image/')`). Новое правило: картинка становится картинкой,
любой другой разрешённый файл — блоком файла.

Пока файл летит на сервер, на его месте стоит блок с именем и полосой
загрузки. Для картинок этого не делали намеренно, здесь — обязательно: 25 МБ
по слабому каналу это десятки секунд, и молчащий интерфейс в такой паузе
читается как поломка.

### Блок

```
┌──────────────────────────────────────────────────────┐
│  ┌────┐                                              │
│  │ PDF│   Договор оферты 2026.pdf                    │
│  └────┘   1,2 МБ                              ↓      │
└──────────────────────────────────────────────────────┘
```

Слева плашка с типом, дальше имя файла как есть (кириллица, пробелы, скобки),
под ним размер. Справа кнопка скачивания; клик по карточке целиком делает то же
самое.

Оформление из токенов: фон `--bg2`, рамка `--border`, радиус `--r-lg`. Карточка
читается как выноска, а не как ссылка в тексте.

В режиме правки блок ведёт себя как картинка: атомарный узел, выделяется
целиком, тащится за ручку, удаляется клавишей.

### Скачивание

Файл **всегда скачивается и никогда не открывается в браузере** — см.
«Безопасность».

## Устройство

### Что переиспользуется как есть

| | Откуда |
|---|---|
| Корень хранилища | `KNOWLEDGE_MEDIA_ROOT` |
| Адресация содержимым | имя файла — sha256, каталоги шардируются по парам hex |
| Отдача без блокировки воркера | `X-Accel-Redirect` во внутреннюю локацию nginx |
| Работа без nginx | запасной путь через `FileResponse` |
| Модель прав | таблица использований: файл виден, если виден хоть один документ, где он вставлен |
| Уборка | задача сбора осиротевших записей по живым документам |
| Ограничение частоты загрузок | scope `knowledge_upload` |

### Общий слой хранения

`images.store_upload` уже делает всё, что нужно файлу: потоковый подсчёт
sha256, запись во временный файл, проверка лимита, перенос на постоянное место.
Специфична для картинок только проверка через Pillow.

Поэтому: выделить из него `storage.store_blob(stream, *, max_bytes, probe)` —
общий приём файла, где `probe` отвечает за проверку содержимого. Картинки
передают проверку через Pillow, файлы — проверку по сигнатуре. Дублировать
работу с временными файлами и хешем нельзя: разойдутся — получим два разных
поведения при переполнении диска.

### Модель

```
KnowledgeFile
  id, sha256 (unique), original_name, mime, byte_size,
  path, uploaded_by, created_at

KnowledgeFileUsage
  file, document  (уникальная пара)
```

Отдельная таблица, а не поле «вид» у `KnowledgeImage`: у картинки есть ширина,
высота, состояние оптимизации и пути вариантов — для файла всё это пустое.
Общий столбец, который у половины строк всегда `NULL`, — признак того, что
слиты две разные сущности.

### Узел документа

```json
{ "type": "knowledgeFile",
  "attrs": { "fileId": 42, "name": "Договор оферты 2026.pdf",
             "size": 1258291, "mime": "application/pdf" } }
```

Имя, размер и тип продублированы в узле, чтобы читалка нарисовала карточку без
единого дополнительного запроса — тот же приём, что у картинки с `width` и
`height`.

**Но скачивание берёт имя из базы, а не из узла.** Что бы ни было записано в
документе, отдаётся имя того файла, который действительно загрузили. Подмена в
JSON меняет только надпись на карточке — правами на это уже обладает тот, кто
и так может написать в документе любой текст, так что новых возможностей это не
даёт.

Три списка обязаны сойтись: расширение редактора, `content.py` и таблица
отрисовки читалки. Существующий тест `test_node_lists_in_sync` подхватит новый
узел автоматически.

Проверки в `content.py`: `ALLOWED_FILE_ATTRS = {fileId, name, size, mime}`
плюс общие атрибуты блока; `fileId` — целое (не `bool`), `name` — строка с
потолком длины, `size` — целое в разумных границах, `mime` — из закрытого
списка.

### API

| Метод | Адрес | Кто | Что |
|---|---|---|---|
| POST | `/api/admin/knowledge/files` | admin, superadmin | загрузка (multipart) |
| GET | `/api/admin/knowledge/files/<id>` | любая роль-читатель | скачивание |

Права на скачивание — той же функцией, что у картинок: файл доступен, если
доступен хоть один документ, где он используется. Администраторам — всегда,
иначе только что вставленный файл нельзя было бы скачать до сохранения
документа.

### nginx

Нужны две локации:

- точная на загрузку — `client_max_body_size 26m` (25 МБ плюс запас на
  накладные расходы multipart);
- регулярная на скачивание — с уже существующей зоной ограничения частоты
  `api_media`.

Порядок важен: точное совпадение выигрывает у регулярного, регулярное — у
общего префикса `/api/`. Тот же порядок уже отлажен на картинках.

Внутренняя локация `/internal-media/` покрывает оба каталога — она отображает
корень хранилища целиком.

### Прогресс загрузки

`fetch` не сообщает о ходе отправки. Для полосы прогресса нужен
`XMLHttpRequest` — единственное место, где придётся отойти от общего клиента
API. Обёртку держать в одном файле рядом с загрузкой файлов, в `lib/api.ts` не
тащить: там она никому больше не нужна.

### Чего у файлов нет

Celery не участвует: у файла нет вариантов, сжимать нечего, состояния
оптимизации не существует. Загрузка файла проще загрузки картинки, а не
сложнее.

## Безопасность

Здесь файлы принципиально опаснее картинок, и это определяет три обязательных
условия.

**Суть угрозы.** Файл, отданный с нашего домена, наследует доверие к домену.
PDF с активным содержимым или HTML-файл, открытые по адресу
`develop-kotokod.ru/...`, исполняются в контексте нашего сайта: видят куки
сессии и обходят политику безопасности, потому что для браузера это «свой»
источник.

**Условие 1. Всегда `Content-Disposition: attachment`.** Браузер скачивает и не
показывает. Это одна строка, и она снимает основную часть угрозы.

**Условие 2. Всегда `X-Content-Type-Options: nosniff`.** Без него браузер
угадывает тип по содержимому и может решить, что «текстовый» файл на самом деле
разметка.

**Условие 3. Белый список, а не чёрный.** Чёрный список расширений всегда
дырявее: забытое расширение — это дыра, забытое разрешение — это всего лишь
неудобство.

**Проверка двойная: расширение И сигнатура.** Расширение без сигнатуры
пропускает исполняемый файл, переименованный в `.pdf`. Сигнатура без расширения
пропускает `.pdf`, внутри которого разметка. Нужны оба.

Сигнатуры: PDF — `%PDF-`; форматы OOXML и OpenDocument — сигнатура zip
`PK\x03\x04` (они и есть zip-архивы); старые форматы Office — сигнатура OLE;
RTF — `{\rtf`; zip — та же zip. Для `txt` и `csv` сигнатуры не существует;
они допускаются по расширению — при принудительном скачивании текстовый файл
безопасен.

Отдельно: docx и zip неотличимы по сигнатуре. Это не проблема, потому что zip
разрешён и так.

**Имя файла в заголовке.** Кодировать по RFC 5987 (`filename*=UTF-8''…`) с
запасным `filename=` из безопасных символов. Наивная подстановка кириллического
имени в заголовок либо разваливает имя, либо открывает подстановку заголовков
через перевод строки в имени.

### Остаточные риски — названы сознательно

**Антивируса нет.** ClamAV на VPS с двумя ядрами и двумя гигабайтами занимает
около гигабайта только под демона с базами. Загружать файлы могут лишь
администраторы, скачивают сотрудники — угроза узкая. Решение осознанное; если
круг загружающих расширится, вопрос надо открыть заново.

**Архив-бомба.** Zip на 25 МБ может разворачиваться в гигабайты. Нам это не
вредит — мы архивы не распаковываем никогда. Вред возможен только тому, кто
откроет такой файл у себя, и от этого защищает антивирус на его машине.

## План работ

Спека утверждена, план реализации — отдельным документом
(`docs/superpowers/plans/`), по обычному порядку раздела.

Ориентировочная последовательность: общий слой хранения → модель и миграция →
проверка содержимого → API загрузки и скачивания → nginx → белый список узла →
расширение редактора и блок → отрисовка в читалке → уборка осиротевших →
тесты на каждом шаге.
