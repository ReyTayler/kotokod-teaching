# График работы преподавателя — дизайн

Дата: 2026-11-18. Статус: утверждён владельцем, реализация не начата.

## Цель

Преподаватель (и сотрудники за него) задаёт окна, в которые ему можно ставить уроки — по образцу букинг-сервисов (Cal.com, Calendly, YCLIENTS). Открытые окна в недельной сетке белые, остальное серое. Окна служат **подсказкой**: блокера на постановку уроков вне окон **нет** (явное решение владельца).

## Решения владельца

| Вопрос | Решение |
|---|---|
| Модель окон | Недельный шаблон + исключения на конкретные даты (как Cal.com/Calendly) |
| Чьи окна | Только преподавателя. Редактируют: сам преподаватель (teacher SPA) и manager/admin/superadmin (карточка преподавателя в admin) |
| Где виден фон белое/серое | Редактор (обе SPA) + «Календарь» teacher SPA + «Календарь» admin при выбранном одном преподавателе |
| Подсказка при постановке урока/группы | Не в этой итерации |
| Шаг сетки | 30 минут, диапазон 08:00–22:00 (28 ячеек на день) |
| Вид редактора | Сетка с закраской + текстовая сводка и список исключений справа (вариант C) |
| Хранение | Интервалы времени (не битовые маски, не развёртка по датам) |
| Название раздела | «График работы» |

## Бэкенд

### Приложение `apps/availability`

Отдельное Django-приложение: доступность («когда может») — отдельный домен от `scheduling` («что запланировано»). Структура — стандартная для проекта: `models.py`, `services.py`, `serializers.py`, `views.py`, `urls.py`, `admin_urls.py`, `tests/`.

### Модели

Обе модели — `@pghistory.track(InsertEvent(), UpdateEvent(), DeleteEvent())`, запись в `apps/changelog/registry.py`, метки мутирующих URL — в `apps/changelog/labels.py`.

**`AvailabilityRule`** (`teacher_availability_rules`) — недельный шаблон:
- `teacher` FK → `teachers` (`on_delete=CASCADE`)
- `day_of_week` int 0–6, конвенция **Вс=0** (как `group_schedule_slots.day_of_week`)
- `start_time`, `end_time` — `TimeField`
- индекс `(teacher, day_of_week)`

**`AvailabilityOverride`** (`teacher_availability_overrides`) — исключения на дату:
- `teacher` FK → `teachers` (`on_delete=CASCADE`)
- `date`
- `start_time`, `end_time` — nullable; обе NULL = «весь день закрыт» (ровно одна такая строка на дату, без интервальных строк рядом)
- индекс `(teacher, date)`

Семантика: если на дату есть хоть одна строка исключения, она **целиком заменяет** шаблон этого дня.

CHECK-ограничения (обе таблицы, где применимо):
- `start_time < end_time`
- минуты `start_time`/`end_time` ∈ {0, 30}, секунды = 0
- `start_time >= 08:00`, `end_time <= 22:00`
- `day_of_week BETWEEN 0 AND 6`
- override: `(start_time IS NULL) = (end_time IS NULL)`

### Сервис `apps/availability/services.py`

- `get_effective_windows(teacher_id, date_from, date_to) -> dict[date, list[tuple[time, time]]]` — шаблон, поверх которого применены исключения. Ровно два запроса (правила преподавателя + исключения в диапазоне), без N+1.
- `has_schedule(teacher_id) -> bool` — есть ли хоть одно правило или исключение.
- `replace_template(teacher_id, intervals)` — атомарная замена всего шаблона (delete + bulk insert в одной транзакции), с нормализацией: соседние/пересекающиеся интервалы одного дня склеиваются.
- `replace_week(teacher_id, monday, days)` — сохранение конкретной недели: по каждому дню, отличающемуся от шаблона, — заменить исключения этого дня (пустой день → одна строка «закрыт»); по дню, совпавшему с шаблоном, — удалить исключения. Даты в прошлом (раньше «сегодня» по МСК) — отказ.
- `clear_override(teacher_id, date)` — удалить исключения даты (сброс к шаблону); прошлая дата — отказ.
- След изменений — «Журнал изменений» (pghistory + метки `schedule.*` в `labels.py`), **не** `log_event`: журнал ИБ — для событий безопасности, мутации расписания туда не пишутся (конвенция `scheduling`). Сервис меняет только реально изменившиеся дни — без лишних событий в журнале. Параллельные сохранения сериализуются `SELECT … FOR UPDATE` строки преподавателя.

### API

Валидация в DRF-сериализаторах: формат `HH:MM`, кратность 30 мин, границы 08:00–22:00, `start < end`. Пересечения/соседство не ошибка — склеиваются сервисом.

Путь — `work-schedule`, не `schedule`: `/api/schedule` занят стражем удалённого legacy-эндпоинта с ПДн (`TestRemovedLegacyEndpoints`), он обязан отдавать 404.

Teacher (`IsTeacher`, преподаватель — **только из учётки**, не из запроса):
- `GET /api/work-schedule/template` → `{ days: {"0"…"6": [["HH:MM","HH:MM"],…]}, upcoming_overrides: [{date, intervals}] }` (исключения с сегодняшнего дня, `intervals: []` = день закрыт); `PUT /api/work-schedule/template` — `{ days }` (все 7 ключей; отсутствующий/пустой день = закрыт)
- `GET /api/work-schedule?from=&to=` → `{ has_schedule, windows: {date: [[start,end],…]}, override_dates: [date] }`
- `PUT /api/work-schedule/week` — `{ monday, days: {date: [[start,end],…]} }`
- `DELETE /api/work-schedule/overrides/<date>`

Admin (`IsManagerOrAdmin`) — те же операции под `/api/admin/teachers/<id>/work-schedule/…`. Подключение в `config/urls.py` — до `path('api/admin/teachers', …)` и до общего `/api` (порядок маршрутов проекта).

Архивный преподаватель (`active=false`): GET работает, мутации — 400.

### Фон в календаре

`/api/calendar` (teacher) и `/api/admin/calendar` (когда передан `teacher_id`) добавляют в ответ поле `availability` = `windows` за тот же диапазон, либо `null`, если у преподавателя нет графика (`has_schedule=false`) или в admin не выбран преподаватель.

## Фронтенд

### Общий компонент `AvailabilityEditor`

Место: `journal_django/frontend/admin-src/src/shared/availability/`; teacher импортирует через `@shared` (как `CalendarView`). Компонент презентационный: данные и мутации передаёт обёртка каждой SPA (свои хуки и URL) — паттерн `CalendarPage`/`AdminCalendarPage`.

Устройство:
- Переключатель «Шаблон недели | Конкретная неделя ‹ даты ›».
- Сетка 7 дней × 28 строк по 30 мин (08:00–22:00). Цвета — только токены `tokens.css` (открыто — поверхность, закрыто — приглушённый токен); токены, используемые в shared-CSS, должны быть в **обоих** `tokens.css`.
- Закраска: `pointerdown` на ячейке фиксирует режим жеста (серая → красим белым, белая → серым); протяжка применяет этот режим, без мерцания туда-обратно. Мышь/перо — протяжка; касание (`pointerType='touch'`) — тап-переключение одной ячейки, прокрутка страницы пальцем не ломается.
- Если в календаре нет уроков, но график задан, недельная сетка всё равно показывается (с фоном), а не заглушка «занятий нет».
- В режиме «Конкретная неделя»: дни с исключением помечены в заголовке + кнопка «↺ к шаблону»; уроки этой недели (из календарного эндпоинта) — полупрозрачными блоками поверх, только как подсказка. Прошедшие недели — только просмотр.
- Справа сводка: окна текстом («Пн 10:00–14:00»), «Итого N ч/нед», список будущих исключений с удалением в один клик.
- «Сохранить» / «Отменить» видны только при изменениях; смена недели/режима с несохранёнными правками — подтверждение; закрытие/перезагрузка страницы — `beforeunload`. Блокировка ухода по маршруту/вкладке — вне рамок (YAGNI).
- Никаких native form-элементов в admin (используем существующие компоненты).

Мутации — TanStack Query, после успеха инвалидируются ключи графика и календаря.

### Размещение

- Teacher SPA: пункт меню **«График работы»**, маршрут `/schedule`, рядом с «Календарь».
- Admin: вкладка **«График работы»** в карточке преподавателя, `?tab=schedule`.

### Фон в `WeekGrid`

Необязательный проп `availability` (вид «Список»/`DayList` — не сетка времени, фона там нет). Если задан — колонка дня закрашивается серым, итоговые окна рисуются белыми прямоугольниками **под** блоками уроков. Если `null`/не передан — сетка как сейчас. В месячном виде фона нет.

## Краевые случаи

- Нет графика → фона нет (не «всё серое»): иначе после выкатки календари всех преподавателей станут серыми.
- Прошлые даты — исключения не создаются/не удаляются.
- Архивный преподаватель — только просмотр.
- Одновременная правка — «последний сохранивший прав»; шаблон заменяется целиком транзакционно; история — в pghistory/журнале изменений.

## Производительность

Итоговые окна — два индексированных запроса на одного преподавателя за диапазон; в календарь подмешиваются только при одном преподавателе. Кэш не нужен.

## Тесты (pytest, полный прогон `pytest -q`)

- Сервис: применение исключений, «день закрыт», склейка интервалов, `replace_week` (сброс совпавших с шаблоном дней), отказ на прошлые даты, `has_schedule`.
- CHECK-ограничения в БД.
- API: RBAC (преподаватель не видит/не правит чужой график; manager/admin — правят; аноним — 401/403), валидация шага 30 мин и границ, архивный преподаватель.
- Поле `availability` в обоих календарных эндпоинтах (есть график / нет / admin без преподавателя).
- `test_registry_covers_all_tracked_models` проходит с новыми моделями.

## Вне рамок

- Подсказка «вне окон» при создании группы/переносе урока (следующая итерация).
- Блокер постановки уроков вне окон — не нужен (решение владельца).
- Графики у учёток, не привязанных к преподавателю.
