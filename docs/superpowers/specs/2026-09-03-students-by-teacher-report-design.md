# Отчёт «Ученики по преподавателям» (за месяц)

Дата: 2026-09-03. Статус: утверждён, к реализации.

## Задача

Excel-выгрузка за выбранный месяц: кто из учеников у какого преподавателя
занимается и сколько уроков отзанимался. Ученик, занимающийся в нескольких
группах одновременно, даёт по строке на каждую группу — со своим
преподавателем.

## Единица строки

Пара «ученик × группа». Пара попадает в отчёт, если выполняется хотя бы одно:

* членство ученика в группе активно (`group_memberships.active = true`);
* в выбранном месяце есть занятия этой группы, где ученик отмечен.

Второе условие намеренно шире первого: ученик, ходивший в июле и ушедший в
августе, обязан остаться в июльском отчёте — иначе цифры прошлых месяцев
менялись бы задним числом.

Ученики без единой группы в отчёт не попадают: у них нет преподавателя, строка
была бы пустой.

## Колонки

| Колонка | Содержимое |
|---|---|
| Группа | `groups.name` |
| Преподаватель | `groups.teacher.name` — **основной преподаватель группы на текущий момент** |
| Ученик | `students.full_name` |
| Уроков у группы за месяц | сумма весов курсовых занятий группы в месяце |
| Посещено учеником | сумма весов посещённых этим учеником занятий |
| Направление | `groups.direction.name` |

«Уроков у группы за месяц» — знаменатель, с которым сравнивают посещения
ученика: сколько занятий он должен был посетить. Считаются только курсовые типы
(`COURSE_LESSON_TYPES` = `regular`, `substitution`, `reschedule`). Доп.урок и
сгорание адресные — это факты конкретного ученика, а не сетки группы, поэтому
её они не удлиняют. Следствие: у ученика, отработавшего пропуск, «посещено»
может быть больше, чем провела группа. Это не дефект, а видимая отработка.

**Из сетки вычитаются неоплачиваемые пропуски этого ученика**
(`lesson_attendance.unpaid_skip`): такие занятия он не посещает и не оплачивает
(перевод, заморозка), спрашивать их с него нельзя. Поэтому колонка считается на
пару «ученик × группа», а не на группу: у двух учеников одной группы числа
законно разойдутся, а у стоявшего весь месяц на неоплачиваемом пропуске будет
0 — при том, что группа занималась. Отрицательной норма не бывает: если
пропусков помечено больше, чем занятий в сетке, показывается 0.

Направление — свойство группы, не ученика: ученик из двух групп разных
направлений даёт две строки с разными направлениями.

**Преподаватель — свойство группы, не занятия.** Фактические замены
(`lessons.teacher_id` ≠ `groups.teacher_id`, поле `original_teacher_id`) в
отчёте не учитываются: спрашивали «преподаватель ученика на данный момент».
Поэтому смена преподавателя группы задним числом меняет и прошлые отчёты — это
осознанный выбор, а не дефект.

## Что считается посещённым уроком

Берутся строки `lesson_attendance` с `present = true` за занятия месяца
(`lessons.lesson_date` внутри месяца по МСК), **кроме** `lesson_type = 'burned'`.

Исключение сгораний — не косметика: сгорание материализуется отдельной
записью-уроком с `present = true` (см. `apps/extra_lessons/services.py`), то
есть наивный фильтр по `present` посчитал бы списанный урок как посещённый.

Считаются: обычные занятия группы, отработки пропусков (`lesson_type='extra'`,
kind `makeup`), доп.уроки сверх курса, бесплатные занятия (`is_free`) — ученик
на них реально был. Не считаются: пропуски, сгорания, неоплаченные пропуски
(`unpaid_skip`, они уже `present = false`).

**Единица — урок, не занятие.** Действует инвариант half-lesson: занятие
длиной 45 минут = 0,5 урока, иначе 1. Вес берётся с самого занятия
(`lessons.lesson_duration_minutes`), не с группы, — у отработок длительность
своя. Итог — кратное 0,5 число, как прогресс курса и продления.

Доп.урок засчитывается в месяц своего проведения, а не месяц пропуска, — так же,
как в финансах и отчёте по посещаемости.

## Лист

Один лист «Ученики по преподавателям». Плоский список без служебных строк
итогов — чтобы работали автофильтр и сводные таблицы Excel. Сортировка:
преподаватель → группа → ученик. Шапка закреплена, автофильтр включён.

Имя файла: `students_by_teacher_YYYY-MM.xlsx`.

## Реализация

Отчёт самодостаточен (как `builders/retention.py`), CLI-двойника не требует.

1. `apps/reports/models.py` — `ReportType.STUDENTS_BY_TEACHER = 'students_by_teacher'`.
2. `apps/reports/builders/students_by_teacher.py` — `collect_month()`,
   `build_workbook()`, `render_bytes()`, `build(month)`.
3. `apps/reports/serializers.py` — `StudentsByTeacherParamsSerializer(_MonthStringSerializer)`
   (месяц `YYYY-MM`, не в будущем).
4. Регистрация в `services._BUILDERS` и `views._PARAM_SERIALIZERS`.
5. `frontend/admin-src/src/lib/reports.ts` — константа и карточка в `REPORT_TYPES`.
6. `apps/reports/tests/test_students_by_teacher.py`.

RBAC, постановка в Celery, скачивание по `task_id` и аудит — уже общие для
раздела, отдельной работы не требуют.

## Производительность

Три запроса, все с агрегацией на стороне Postgres, без N+1:

1. агрегат `lessons` за месяц по курсовым типам, `GROUP BY group_id` — сетка
   группы (общая для всех её учеников, отсюда отдельный запрос, а не подзапрос
   на строку);
2. агрегат `lesson_attendance` за месяц по `unpaid_skip = true`,
   `GROUP BY (student_id, group_id)` — личный вычет из сетки;
3. агрегат `lesson_attendance` за месяц, `GROUP BY (student_id, group_id)`,
   сумма весов через `CASE WHEN lesson_duration_minutes = 45 THEN 0.5 ELSE 1`;
4. активные членства с именами ученика, группы, преподавателя и направления.

Вычитание нормы — проход по собранным парам в памяти, без запроса на строку.

Оба фильтруются по диапазону дат месяца — под запрос ложится существующий
индекс `lessons_teacher_date_idx` / индексы по `lesson_date`.
