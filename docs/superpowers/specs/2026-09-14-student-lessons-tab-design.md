# Вкладка «Уроки» в карточке ученика

Дата: 2026-09-14
Статус: утверждён, к реализации

## Задача

В карточке ученика (Admin SPA) появляется отдельная вкладка со всеми его уроками.
Строка — один урок ученика; видно, какого типа было занятие, где и с кем оно прошло
и сколько денег этим уроком было отработано.

Сейчас такой картины нет нигде: вкладка «Обучение» показывает прогресс по группам,
«Финансы» — оплаты и общий остаток, но связи «конкретный урок → конкретные деньги»
не видит ни один экран.

## Состав строк

Строка = запись `lesson_attendance` ученика с `present=true`. Это ровно четыре типа
из задачи и ничего лишнего:

| Тип строки | Как определяется |
|---|---|
| Сгоревший | `lessons.lesson_type = 'burned'` |
| Доп.урок | `lessons.lesson_type = 'extra'` |
| Бесплатный | `lesson_attendance.is_free = true` |
| Обычный | всё остальное (`regular` / `substitution` / `reschedule`) |

Порядок проверки именно такой: сгорание и доп.урок сами по себе бесплатными не бывают,
поэтому `lesson_type` смотрим раньше флага `is_free`.

Пропуски (`present=false` — и ждущие решения, и неоплачиваемые) во вкладку **не попадают**
(решение пользователя). Их место — очередь резолюций и вкладка «Обучение».

## Колонки

| Колонка | Источник |
|---|---|
| ID | `lessons.id` |
| Дата занятия | `lessons.lesson_date` |
| Сохранён | `lessons.submitted_at` |
| Тип | выводится по таблице выше |
| Продолжительность | `lessons.lesson_duration_minutes`, в минутах |
| Группа | `groups.name` (ссылка на карточку группы) |
| Преподаватель | `teachers.full_name` (ссылка на карточку преподавателя) |
| Направление | `directions.name` — направление **группы** урока |
| Признано | FIFO-сумма, списанная этим уроком (см. ниже) |

Сортировка: `submitted_at DESC, lessons.id DESC` — по убыванию даты сохранения урока.
Обе даты (занятия и сохранения) выводятся, потому что они часто расходятся и без них
порядок строк выглядел бы случайным.

Колонка «Продолжительность» нужна как объяснение суммы: у 45-минутного занятия вес
0,5 урока (инвариант half-lesson), поэтому признаётся половина цены.

## «Признано» — точный FIFO по уроку

Смысл: сколько рублей конкретно этот урок списал с конкретных оплат ученика.

Реализация — разрез внутри общей функции `compute_fifo` (`apps/finances/fifo.py`),
а не отдельный проход. Вторая реализация очереди FIFO разъехалась бы с первой, и
вкладка перестала бы сходиться с «Отчётом по поступлениям и выручке» и дашбордом.

Изменения:

* Запись потребления может нести `lesson_id` (в запросе он уже выбирается, просто
  не доезжает до словаря).
* `compute_fifo` копит два новых разреза:
  * `worked_off_by_lesson: {lesson_id: Decimal}` — сколько денег погашено этим уроком;
  * `over_consumed_by_lesson: {lesson_id: Decimal}` — сколько уроков (units) этой
    записи прошло сверх оплаченного остатка.
* Значения — точный Decimal без округления, как у остальных «платёжных» разрезов;
  округление до копеек делает потребитель, один раз на строку.
* Записи без `lesson_id` (синтетические возвраты) в разрезы не попадают.

Существующие ключи возврата не меняются: текущие потребители (`dashboard`, `reports`,
`revenue_forecast`, `student_month`) читают словарь по именам полей, новые ключи их
не задевают.

### Пограничные случаи

* **Бесплатное занятие** — в FIFO-потребление не входит вовсе (`is_free=False` в фильтре),
  в карте его нет → `0,00 ₽`. Это честный ноль: денег за него не берут.
* **Урок в долг** (оплаченные уроки кончились) — `0,00 ₽` плюс серая пометка «в долг».
  Оценку по цене последней оплаты не показываем: сумма колонки должна сходиться с
  признанной выручкой.
* **Возврат средств** гасит партии как обычно, поэтому урок, проведённый после возврата,
  честно может оказаться «в долг».
* **Половинный урок** (45 мин) — признаётся половина цены партии; объясняется колонкой
  «Продолжительность».
* Урок может гаситься **двумя партиями** сразу (граница абонементов) — в колонке
  сумма обеих частей.

## Бэкенд

Эндпоинт: `GET /api/admin/students/<id>/lessons`, `permission_classes = [IsManagerOrAdmin]`
— доступ у всех ролей админки, как у соседних вкладок карточки. Пагинация —
`StandardPagination` (50 строк, конверт `{rows, total, page, page_size}`).

Данные строк — один запрос `LessonAttendance.filter(student_id=…, present=True)` с
`select_related` на урок, группу, направление и преподавателя: без N+1.

Деньги — карта `lesson_id → признано`, построенная по **всей** истории ученика
независимо от запрошенной страницы. Иначе неизвестно, какие абонементы к этому моменту
погашены. У одного ученика это десятки строк, расчёт дешёвый.

Построение партий и потреблений для одного ученика уже есть в
`apps/finances/repository.py::student_fifo_remaining`. Общий кусок выносится в
приватный хелпер и переиспользуется — двух построений партий в модуле быть не должно.

Новая функция репозитория отдаёт карту `{lesson_id: {'recognized': Decimal, 'is_debt': bool}}`;
вьюха склеивает её со строками посещаемости.

## Фронтенд

Новая вкладка `lessons` с меткой «Уроки» — между «Обучение» и «Финансы»
(`STUDENT_TABS` в `pages/students/StudentDetailPage.tsx`). Значение вкладки живёт в
`?tab=lessons`, как у остальных.

* `pages/students/StudentLessonsBlock.tsx` — таблица на `components/table/DataTable`
  плюс `Paginator`, номер страницы в состоянии компонента.
* `hooks/useStudentLessons.ts` — `useQuery` с `placeholderData: keepPreviousData`
  (обязателен во всех server-paginated хуках).
* Группа и преподаватель — `EntityLink`, как в остальных таблицах раздела.
* Ярлыки типов — новый набор в `lib/labels.ts`. Существующий `LESSON_TYPE_LABELS`
  не подходит: он про сырой `lesson_type` и не знает «сгоревшего» и «бесплатного».
* Суммы — `fmtRub`, даты — `fmtDate` / `fmtDateTime` из `lib/format`.
* Цвета, отступы и радиусы — только токены (`styles/tokens.css`), новых hardcoded
  значений не заводим. Пометка «в долг» — существующий приглушённый тон текста.

## Тесты

`pytest` (из `journal_django/`, полный прогон, не по приложениям):

* Разрез FIFO по уроку: обычный урок; 45-минутный (полцены); доп.урок; сгорание;
  бесплатный (0 ₽ и отсутствие в потреблении); урок в долг; урок после возврата;
  урок на стыке двух партий (сумма двух частей).
* Сумма `worked_off_by_lesson` по всем урокам равна `worked_off_total` — разрез не
  расходится с итогом.
* Эндпоинт: состав строк (пропуски не попадают), порядок сортировки, выводимый тип
  для каждого из четырёх случаев, пагинация, RBAC (менеджер видит, преподаватель — нет).
