# Раздел «Зарплата» в кабинете преподавателя — дизайн

**Дата:** 2026-07-31
**Статус:** согласовано, к реализации
**Область:** teacher SPA (`journal_django/frontend/teacher-src`), `apps/payroll`

## Задача

Преподаватель не видит своих денег нигде. Расчётный лист есть только у админа
(`/api/admin/payroll`, `IsSuperAdmin`). Нужен раздел, где преподаватель видит
сумму за месяц и **понимает, откуда взялась каждая выплата за урок**.

Понятность — главное требование, а не сам факт отображения суммы. Строка
«800 ₽» без объяснения порождает вопросы к администрации; строка
«пришли 4 из 5 · 4 × 200 ₽ = 800 ₽» — не порождает.

## Решения (согласованы с пользователем)

| Вопрос | Решение |
|---|---|
| Размещение | Новый раздел «Зарплата» в верхнем меню teacher SPA |
| Период | Помесячно, переключатель ◀ ▶, открывается на текущем месяце |
| Штрафы | Показывать явно: начислено → штраф → к выплате |
| Справочник ставок | Не нужен. Правило живёт в строке конкретного урока |

## Что уже есть в проекте

- `apps/payroll/calculator.py` — единственный источник ставок:
  `PAY_RATES = {halfLesson: 250, smallGroup: 500, smallPartial: 300, perStudent: 200}`,
  `calculate_payment(total, present, is_half)`, `calculate_penalty(...)` (40 ₽/чел,
  если отчёт сдан не в день урока), `calculate_extra_lesson_payment(present)` (флет 200 ₽).
- Таблица `payroll` — 1:1 с `lessons`: `total_students`, `present_count`,
  `payment`, `penalty`. Доп.уроки и сгорания — отдельные `Lesson`
  (`lesson_type` = `extra` / `burned`) со своими строками payroll.
- `GET /api/lessons` (teacher SPA) уже отдаёт `payment`/`penalty` по каждому
  уроку со скоупом по JWT. Хук `useMyLessons` написан, но нигде не используется.

## Архитектура

### Эндпоинт

```
GET /api/my-payroll?month=YYYY-MM      permission_classes = [IsTeacher]
```

Монтируется в `config/urls.py` как `path('api/my-payroll', include('apps.payroll.teacher_urls'))`
— по образцу `apps/extra_lessons/teacher_urls.py` (`api/extra-lessons`). Строго
**после** блока `api/admin/…`, как все teacher-маршруты.

`month` необязателен; по умолчанию — текущий месяц по МСК (`apps.core.utils.dates.msk_now`).
Невалидный формат → 400 `{"error": "..."}`.

**RBAC:** `teacher_id` берётся ТОЛЬКО из `request.user.teacher_id` (JWT). Параметра
`teacher_id` в запросе нет и быть не должно — иначе преподаватель прочитает чужую
зарплату.

### Слои

| Файл | Ответственность |
|---|---|
| `apps/payroll/explain.py` | **Новый. Чистый, без БД.** Превращает данные строки payroll в расшифровку (правило + текст + пояснения). Тестируется отдельно от Django. |
| `apps/payroll/repository.py` | `teacher_month_entries(teacher_id, first_day, last_day)` — строки payroll за месяц + `excluded_counts(lesson_ids)` — сколько учеников исключено из headcount. |
| `apps/payroll/services.py` | `my_payroll_month(teacher_id, month)` — собирает строки, зовёт `explain`, считает итоги в `Decimal`. |
| `apps/payroll/views.py` | `MyPayrollView` — разбор `month`, `IsTeacher`. |
| `apps/payroll/teacher_urls.py` | **Новый.** Маршрут. |

### Как строится расшифровка (ключевое)

`explain.py` **не угадывает** правило по признакам урока. Он прогоняет тот же
`calculate_payment` из `calculator.py` и сверяет результат с суммой, лежащей в БД:

1. Если `present_count == 0` → правило `none` («никто не пришёл — оплата не начисляется»).
2. Для `lesson_type ∈ {extra, burned}` сначала проверяется флет-200
   (`calculate_extra_lesson_payment`), затем индив-ветка `calculate_payment(total=1, …)`
   — доп.урок сверх курса для индива оплачивается как обычный индивидуальный
   урок (250 за 45 мин / 500 за полный).
3. Для остальных типов — `calculate_payment(total_students, present_count, is_half)`,
   где `is_half = lesson_duration_minutes == 45`.
4. Если ни один кандидат не совпал с сохранённой суммой — правило `adjusted`:
   «сумма скорректирована администратором». Это честный ответ на факт, что
   `PATCH /api/admin/payroll/:id` позволяет админу переписать выплату вручную.

Так ставки не дублируются: изменили `PAY_RATES` — расшифровка меняется вместе с
расчётом, разъехаться они не могут.

**Коды правил:**

| code | text | note |
|---|---|---|
| `half_lesson` | `4 × 250 ₽` | занятие 45 минут — 250 ₽ за каждого пришедшего |
| `small_group_full` | `500 ₽` | занималось до 2 человек, пришли все |
| `small_group_partial` | `300 ₽` | занималось до 2 человек, пришли не все |
| `per_student` | `4 × 200 ₽` | группа от 3 человек — 200 ₽ за каждого пришедшего |
| `extra_flat` | `1 × 200 ₽` | дополнительное занятие — 200 ₽ за каждого пришедшего |
| `extra_individual` | `500 ₽` | индивидуальное дополнительное занятие — как обычный урок |
| `none` | `0 ₽` | никто из учеников не был засчитан |
| `adjusted` | `800 ₽` | сумма скорректирована администратором |

**Штраф** объясняется тем же приёмом: если `penalty == 40 × present_count`, отдаём
`penaltyNote` вида «отчёт сдан 05.07, урок был 03.07 — 40 ₽ × 4». Дата сдачи —
`lessons.submitted_at`, приведённая к МСК. Если сумма штрафа не совпала с формулой
(ручная правка админа) — нейтральное «удержание, изменено администратором».
Штраф `0` → `penaltyNote: null`.

### Исключённые из оплаты ученики

`total_students` в payroll — это **не** размер группы: из headcount исключены
`is_free` (бесплатное занятие) и `unpaid_skip` (неоплачиваемый пропуск), см.
`apps/lessons/services.py::record_lesson`. Без пояснения преподаватель видит
«пришли 4 из 4» в группе из пяти человек и считает это ошибкой системы.

Поэтому по каждому уроку отдаётся `excludedNote`, например
«1 ученик не учтён: бесплатное занятие». Данные — одним сгруппированным запросом
по `lesson_attendance` для всех уроков месяца (не N+1).

### Контракт ответа

camelCase — как весь teacher SPA (`MyLessonSerializer`, `/api/calendar`).
Деньги — строками с масштабом (`"800.00"`), тоже как в существующем контракте;
фронт приводит `Number()`. Итоги суммируются в `Decimal` на сервере.

```jsonc
{
  "month": "2026-07",
  "monthLabel": "Июль 2026",
  "totals": {
    "lessons": 22, "presences": 68,
    "payment": "24800.00", "penalty": "480.00", "net": "24320.00"
  },
  "rows": [{
    "lessonId": 1234,
    "date": "2026-07-03",
    "group": "Python Пн 17:00",
    "direction": "Python",
    "directionColor": "#4F59F9",
    "lessonNumber": "12.0",
    "kind": "regular",              // regular | substitution | reschedule | extra | burned
    "durationMinutes": 60,
    "totalStudents": 5,
    "presentCount": 4,
    "payment": "800.00",
    "penalty": "160.00",
    "net": "640.00",
    "rule": { "code": "per_student", "text": "4 × 200 ₽",
              "note": "группа от 3 человек — 200 ₽ за каждого пришедшего" },
    "penaltyNote": "отчёт сдан 05.07, урок был 03.07 — 40 ₽ × 4",
    "excludedNote": "1 ученик не учтён: бесплатное занятие",
    "adjusted": false
  }]
}
```

Порядок строк — по дате по убыванию (свежие сверху), вторично по `-id`.
`totals.lessons` — число строк, `totals.presences` — сумма `presentCount`.
`monthLabel` формируется из явной таблицы русских названий месяцев (локаль Django
на сервере не настраивается ради одной подписи).

### Производительность

Один запрос на строки месяца (`select_related('lesson__group__direction')`,
индекс `lessons_teacher_date_idx` уже есть) + один сгруппированный по
`lesson_attendance`. Порядок 30 строк на преподавателя в месяц — пагинация не
нужна. Итоги считаются из уже выбранных строк, отдельного агрегата нет.

## UI

Раздел «Зарплата» в верхнем меню (пятый пункт, иконка кошелька).

```
◀   Июль 2026   ▶                        ▶ заблокирована на текущем месяце

┌──────────────────────────────────────────────────┐
│  К выплате                                       │
│  24 320 ₽                                        │
│  начислено 24 800 ₽   ·   штрафы −480 ₽          │
│  22 урока · 68 присутствий                       │
└──────────────────────────────────────────────────┘

│03.07 Пн   Python Пн 17:00 · урок 12              800 ₽
│           пришли 4 из 5 · 4 × 200 ₽
│           1 ученик не учтён: бесплатное занятие

│05.07 Ср   Скретч Ср 15:00 · урок 8    [Замена]   640 ₽
│           пришли 2 из 2 · 500 ₽
│           −160 ₽ · отчёт сдан 07.07, урок был 05.07
```

- Левая полоска строки — цвет направления (`--subject-*` из `tokens.css`).
- Суммы — `--font-mono`, `font-variant-numeric: tabular-nums`, выравнивание вправо:
  столбец чисел должен читаться сверху вниз.
- Вторая строка — всегда формула. Третья — только когда есть штраф и/или
  исключённые ученики. Штраф — `--danger`.
- Бейджи типа урока: «Замена», «Перенос», «Доп. занятие», «Сгоревшее занятие».
  Обычный урок бейджа не имеет — шум.
- Состояния: скелетон при загрузке, «Не удалось загрузить» при ошибке,
  «В этом месяце уроков ещё не было» при пустом месяце.
- Мобильная раскладка: сумма уходит вправо от заголовка, пояснения — под ним
  во всю ширину.
- Только токены дизайн-системы. Хардкод цветов/радиусов/отступов запрещён
  (`docs/design-system.md`).

**Файлы фронта:** `pages/payroll/PayrollPage.tsx`, `hooks/useMyPayroll.ts`,
`styles/payroll.css`, пункт в `components/shell/TeacherShell.tsx`, роут
`/payroll` в `App.tsx`, типы в `lib/types.ts`.

Запрос — `useQuery` с `placeholderData: (prev) => prev`, чтобы при переключении
месяцев список не мигал (обязательное соглашение проекта).

## Тестирование

**Unit (`apps/payroll/tests/test_explain.py`, без БД):** каждая ветка правил,
включая `none`, `adjusted`, доп.урок флет-200 и индив 250/500; форматирование
текстов; штрафное пояснение; фразы про исключённых учеников (1/несколько,
бесплатное/пропуск/оба).

**API (`apps/payroll/tests/test_my_payroll_api.py`):**
- чужие строки payroll не видны (скоуп по JWT);
- роль не teacher → 403; аноним → 401;
- границы месяца (первый и последний день включены, соседние — нет);
- итоги = сумме строк;
- урок без строки payroll в выдачу не попадает;
- невалидный `month` → 400;
- пустой месяц → `rows: []` и нулевые итоги;
- `assert_num_queries` — фиксированное число запросов независимо от числа уроков.

## Вне области

Экспорт в Excel, графики по месяцам, сравнение с прошлым месяцем, прогноз
выплат, изменение ставок из интерфейса. YAGNI — добавим, если попросят.
