# Переосмысление sidebar в Admin SPA: сворачиваемые группы + мобильный drawer

Дата: 2026-08-25
Статус: утверждено пользователем, готово к планированию

## Задача

Разделов в admin SPA стало 19, сайдбар превратился в длинный плоский список с
надписями-разделителями. Нужно:

1. Спрятать разделы внутрь их смысловых групп — группа раскрывается кликом.
2. На узких экранах вместо всплывающей снизу шторки показывать тот же сайдбар,
   выезжающий слева поверх контента.

Ориентир по взаимодействию — скриншот CRM, приложенный пользователем: строка
группы с иконкой и шевроном, вложенные пункты без иконок.

## Что есть сейчас

- `components/shell/Sidebar.tsx` — 300+ строк: 20 SVG-иконок (`NAV_ICONS`),
  конфиг `NAV_GROUPS` (5 групп), плоский экспорт `NAV_ITEMS`, `Avatar`,
  `PayButton`, `ExtraLessonsBadge` и сама разметка. Группы рисуются плоско:
  заголовок-надпись (`.nav-group__title`) и сразу все пункты.
- `components/shell/MobileNav.tsx` — нижняя шторка (bottom sheet) с плоским
  списком `NAV_ITEMS`; единственный потребитель `NAV_ITEMS`.
- `components/shell/AppShell.tsx` — брейкпоинт `NARROW_BREAKPOINT = 1500`,
  состояния `sidebarOpen` / `mobileOpen`, кнопка-бургер.
- `styles/shell.css` — блоки `.sidebar-*`, `.nav-*`, `.burger-btn`,
  `.mobile-nav*`.
- `styles/base.css` — `.shell` и `.sidebar` (sticky, `height: 100vh`, ширина
  `var(--sidebar-w)` = 224px из `tokens.css`).

Teacher SPA живёт на верхнем navbar со своим `shell.css` и этой правкой не
затрагивается. Бэкенд не затрагивается вовсе.

## Решения (утверждены)

| Развилка | Решение |
|---|---|
| Поведение групп | Аккордеон: открыта ровно одна группа |
| Клик по строке группы | Только разворачивает и сворачивает, никуда не ведёт |
| Мобильный режим | Тот же `Sidebar` слева, `min(280px, 86vw)` плюс затемнение |
| Icon rail на десктопе | Не делаем: кнопка «‹» по-прежнему прячет сайдбар целиком |

## Архитектура

`Sidebar.tsx` разрезается по назначению — сейчас он смешивает данные, атомы и
сборку, и после добавления логики аккордеона стал бы нечитаемым.

| Файл | Ответственность | Зависит от |
|---|---|---|
| `shell/navConfig.tsx` | Данные навигации: `NAV_ICONS`, `NAV_PINNED`, `NAV_GROUPS`, типы `NavItem` и `NavGroup`, `groupKeyOfPath` | `lib/permissions` |
| `shell/NavGroup.tsx` | Одна сворачиваемая группа: строка-кнопка, список пунктов, бейдж | `navConfig`, react-router |
| `shell/Sidebar.tsx` | Сборка: лого, закреплённый блок, группы, футер; состояние аккордеона | `navConfig`, `NavGroup` |
| `shell/SidebarDrawer.tsx` | Мобильная обёртка над `Sidebar` (Radix Dialog) | `Sidebar`, `@radix-ui/react-dialog` |

`MobileNav.tsx` удаляется. `NAV_ITEMS` (плоский список) удаляется вместе с ним —
других потребителей нет.

### Конфиг навигации

```ts
export interface NavItem {
  key: string;
  label: string;
  path: string;
  can?: (role: Role | undefined) => boolean;
}

export interface NavGroup {
  key: string;        // новое: устойчивый ключ для состояния аккордеона
  title: string;      // больше не nullable
  icon: string;       // новое: ключ в NAV_ICONS для строки группы
  items: NavItem[];
}

/** Закреплено сверху, вне групп: «Дашборд» плюс CTA «Внести оплату». */
export const NAV_PINNED: NavItem[] = [
  { key: 'dashboard', label: 'Дашборд', path: '/admin/dashboard' },
];
```

Вынос «Дашборда» в `NAV_PINNED` убирает костыль `gi === 0 && <PayButton />`:
кнопка оплаты рендерится в закреплённом блоке явно, а не «в первой группе».

Состав четырёх групп (после правки от 2026-08-25: «Продления» переехали из
«Финансов» в «Учебную часть», «Отчёты» — из «Финансов» в «Систему»):

| Ключ | Заголовок | Иконка группы | Пункты |
|---|---|---|---|
| `study` | Учебная часть | `group-study` | Ученики, Группы, Преподаватели, Направления, Продления |
| `lessons` | Занятия | `group-lessons` | Уроки, Доп.уроки, Календарь |
| `finance` | Финансы | `group-finance` | Абонементы, Зарплата |
| `system` | Система | `group-system` | Wiki, Отчёты, Настройки, Архив, Учётки, Журнал ИБ, Журнал изменений, Уведомления, Синхро |

Ролевые гейты (`can`) остаются на пунктах. Группа без единого видимого пункта
не рисуется — правило уже есть, переносится как есть.

### Иконки

Иконки показываются **только** у строк групп и закреплённых пунктов. У
вложенных разделов иконок нет — как на скриншоте-ориентире.

Причина не только эстетическая: иконки групп неизбежно дублировали бы иконки
своих же пунктов (шестерёнка у «Системы» и у «Настроек», книга у «Занятий» и у
«Уроков», и так далее). Отступ и отсутствие иконки читаются как вложенность
надёжнее, чем второй ряд значков.

Добавляются четыре SVG в `NAV_ICONS` под ключами `group-study`,
`group-lessons`, `group-finance`, `group-system` — в стиле остальных:
`viewBox="0 0 24 24"`, `fill="none"`, `stroke="currentColor"`,
`strokeWidth="1.8"`, скруглённые концы, размер 16×16.

Иконки существующих пунктов (`students`, `lessons` и прочие) из `NAV_ICONS`
НЕ удаляются: они используются вне сайдбара — проверить потребителей перед
любой чисткой.

### Состояние аккордеона

Живёт в `Sidebar` — единственном месте, где он собирается:

```ts
const [openKey, setOpenKey] = useState<string | null>(() => groupKeyOfPath(pathname));
useEffect(() => {
  const g = groupKeyOfPath(pathname);
  if (g) setOpenKey(g);
}, [pathname]);
```

- При монтировании открыта группа текущего раздела.
- Клик по строке группы: `setOpenKey(k => k === key ? null : key)` — открывает
  её и закрывает предыдущую; повторный клик сворачивает.
- Переход в раздел другой группы (по ссылке со страницы, не из сайдбара)
  автоматически открывает нужную группу.
- Переход внутри той же группы состояние не трогает.
- Если пользователь свернул группу с текущим разделом — она остаётся свёрнутой
  до следующей смены `pathname`. Это осознанное поведение, не баг.

`groupKeyOfPath` — чистая функция в `navConfig.tsx`: ищет группу, чей пункт
совпадает с началом пути (`pathname.startsWith(item.path)`), чтобы вложенные
маршруты вроде `/admin/students/42` тоже подсвечивали свою группу.

Состояние в localStorage НЕ сохраняется: аккордеон полностью выводится из
текущего маршрута, лишняя память тут только запутает.

### Три состояния строки группы

1. **Свёрнута** — приглушённый текст (`--text2`), шеврон вправо.
2. **Свёрнута, внутри активный раздел** — акцентный цвет текста и иконки: видно,
   где находишься, не разворачивая.
3. **Развёрнута** — шеврон повёрнут вниз (CSS-поворот, не второй SVG), под
   строкой список пунктов.

Раскрытие анимируется чистым CSS через `grid-template-rows: 0fr → 1fr` на
обёртке списка — без JS-замеров высоты и без `max-height`-хака с угаданным
числом.

### Бейдж «Доп.уроки»

Красный счётчик необработанных пропусков висит на пункте внутри группы
«Занятия». Свёрнутая группа его прячет — а он существует ровно для того, чтобы
попадаться на глаза.

Правило: **если группа свёрнута, бейдж поднимается на её строку**; развёрнута —
показывается на своём пункте. Хук `usePendingExtraLessonsCount` тот же,
react-query дедуплицирует — второго запроса не появляется.

Обобщать до «суммы бейджей группы» не нужно: бейдж в навигации ровно один
(YAGNI).

## Мобильный drawer

`SidebarDrawer` строится на `@radix-ui/react-dialog` — пакет уже в зависимостях
(`components/ui/Dialog.tsx`). Он бесплатно даёт закрытие по Esc, ловушку фокуса,
возврат фокуса на бургер, блокировку прокрутки страницы, `aria-modal` и портал.
Своего кода на это писать не надо — это прямое требование проекта «не изобретать
велосипед».

Берутся примитивы (`Root`, `Portal`, `Overlay`, `Content`, `Title`), а не готовая
обёртка `Dialog`: у неё своя модальная шапка и `.modal`-стили.

Разметка и стили:

- `Content` — это `.sidebar-drawer`: `position: fixed; inset-block: 0; left: 0;`
  `width: min(280px, 86vw)`, `height: 100dvh`,
  `z-index: calc(var(--z-nav) + 2)`.
- Анимация въезда: `translateX(-100%)` в `0` по data-состоянию Radix
  (`[data-state="open"]` и `[data-state="closed"]`).
- `Overlay` — затемнение справа, переиспользует существующие токены подложки.
- Внутри — тот же `<Sidebar onClose={...} />`. Крестик в шапке сайдбара уже есть
  и закрывает drawer.
- Переопределение: `.sidebar-drawer .sidebar { position: static; height: 100%;
  min-height: 0; border-right: none; }` — базовый `.sidebar` из `base.css` живёт
  как sticky-колонка и внутри фиксированного drawer вёл бы себя неверно.
- Radix требует `Title` для доступности; ставится визуально скрытым
  («Меню разделов»).

`AppShell` упрощается: ветка `isNarrow` рендерит `<SidebarDrawer
open={mobileOpen} onOpenChange={setMobileOpen} />` вместо `<MobileNav>`.
Существующий сброс `setMobileOpen(false)` при смене `pathname` сохраняется.
Брейкпоинт (1500), поведение бургера и кнопки «‹» не меняются.

## Удаляется

- `components/shell/MobileNav.tsx`
- экспорт `NAV_ITEMS`
- блоки `.mobile-nav`, `.mobile-nav-overlay`, `.mobile-nav-handle`,
  `.mobile-nav-list`, `.mobile-nav-item` и их тёмные варианты в `shell.css`
- `.nav-group__title` в прежнем виде — заменяется строкой-кнопкой группы

## Дизайн-система

Никаких хардкод-цветов, радиусов и отступов: только токены из
`styles/tokens.css` (`--text2`, `--text4`, `--accent`, `--accent-soft`,
`--space-*`, `--r-sm`, `--t-fast`, `--ease`, `--z-nav`). Контраст текста групп и
пунктов держать на уровне AA. Обе темы — светлая и тёмная.

## Производительность

Сетевого поведения правка не меняет: тот же один запрос счётчика пропусков.
Аккордеон сокращает число одновременно смонтированных `NavLink` — DOM навигации
становится меньше, а не больше.

## Доступность

- Строка группы — `<button type="button">` с `aria-expanded` и `aria-controls`,
  указывающим на список пунктов.
- Список пунктов свёрнутой группы не должен быть достижим табом. Убирать его
  атрибутом `inert` на обёртке, а не `hidden`: `hidden` снимает элемент с
  раскладки и убивает transition высоты, `inert` же гасит фокус и указатель,
  не мешая анимации.
- Focus-ring остаётся общий из `base.css` (`:focus-visible`).
- Анимации отключаются при `prefers-reduced-motion: reduce`.

## Проверка

Frontend-тестов в admin SPA нет (в `package.json` только `dev`, `build`,
`typecheck`). Приёмка:

1. `npm run typecheck` — чисто.
2. `npm run build` — собирается. Артефакты `admin-dist/` попадают в рабочее
   дерево; это ожидаемо для фронтовой правки, но при коммите проверить
   `git show --stat`.
3. Ручной прогон в браузере:
   - десктоп: аккордеон, автооткрытие группы при переходе по ссылке со
     страницы, свёрнутая группа с активным разделом, бейдж на свёрнутых
     «Занятиях», кнопка «‹» и возврат бургером;
   - узкое окно (менее 1500): drawer выезжает слева, затемнение, Esc, тап по
     подложке, крестик, переход по пункту закрывает drawer, фокус возвращается
     на бургер, страница под drawer не прокручивается;
   - обе темы;
   - роль «менеджер»: скрытые пункты не ломают группы, группа без видимых
     пунктов не рисуется.
