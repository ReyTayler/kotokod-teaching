# Версии мотивации групповых занятий

Дата: 2026-11-22. Дополнение к индивидуальной мотивации от 2026-11-18.

## Правила

- `GroupPayRateVersion` — самостоятельная история ставок, независимая от индивидуальных версий. Выбор по дате занятия: последняя версия с `effective_from <= lesson_date`.
- До первой групповой версии действует прежний калькулятор. Миграция не создаёт версий и не пересчитывает начисления.
- Новая версия — с сегодня по МСК или позже. Версию с прошлой даты нельзя исправить или удалить; начатую сегодня можно исправлять весь день, как индивидуальную.
- Схема `attendance_v1`: сгорание → своя ставка; никто не присутствовал → 0; отработка → своя ставка × присутствие; 45 минут → ставка 45 минут × присутствие; малая группа → фикс за полное/частичное присутствие; большая → ставка × присутствие.
- Начальные значения: граница малой группы 2; полная 500, частичная 300, большая 200 за присутствующего, 45 минут 250 за присутствующего, отработка 200 за присутствующего, сгорание 200 за списание.
- Дополнительный урок сверх курса сохраняет прежнюю особенность: обычная схема с расчётным составом 1. Отработка и сгорание отделены от него.
- Расчётный состав берётся из `LessonAttendance`: `unpaid_skip` исключается из состава и присутствия; бесплатное присутствие учитывается.
- Штраф настраивается отдельно от индивидуальных ставок: включён/выключен, сумма, за занятие/за присутствующего. Начальное значение 40 за присутствующего. Только поздний отчёт преподавателя (`acct:`, `extra:`, `makeup:`); сгорание и административная запись не штрафуются.
- Групповые отмены не оплачиваются. Персональные ставки по-прежнему доступны только для индивидуальных групп.
- Пересчёт после мутации ограничен затронутым периодом групповых уроков. Индив и начисления отмен не затрагиваются. Ручные суммы сохраняются, меняются `calc_*`; при смене получателя ручная правка снимается.
- Снимок `Payroll.group_rate_snapshot` содержит id версии, её параметры и исходные данные расчёта. `rule_note` — пояснение для администратора и преподавателя. Снимки и версии включены в pghistory; откат версий через журнал запрещён.
- Будущие способы расчёта получают новый ключ алгоритма. Код `attendance_v1` сохраняет смысл для старых версий. Произвольных формул в интерфейсе нет.

## API и интерфейс

- Только superadmin: `GET/POST /api/admin/payroll/group-rate-versions`, `PATCH/DELETE …/<id>`.
- `POST …/preview` — чистый расчёт примеров тем же движком, без записи и пересчёта зарплат. Возвращает случаи полной/частичной малой группы, большой группы, 45 минут и нулевого присутствия.
- Мутации возвращают `recalculated`; ограничения даты и уникальности проверяются сервером. Мутации версий сериализованы общим со ставками индива транзакционным advisory-замком.
- «Настройки → Мотивация → Групповые занятия»: история версий, создание с даты, исправление/удаление доступных версий. Форма показывает прежние суммы, новые поля и серверный предпросмотр. На узком экране ставки расположены под соответствующими условиями.

## Проверка

- `python -m pytest apps/payroll/tests` — паритет старого и нового расчёта, параметры, доступ, даты, независимость от индива, снимки, ручные правки, сброс, возврат к прежнему расчёту.
- Тесты `apps/lessons`, `apps/extra_lessons`, `apps/changelog` — регрессии путей записи.
- `npm run typecheck`, `npm run build` в `journal_django/frontend/admin-src`.
- `python journal_django/frontend/tests/group_motivation_ui.py` — синтетический API, Edge, desktop/mobile, светлая/тёмная темы, ошибка сохранения и повтор, неизменяемые прошлые версии.
