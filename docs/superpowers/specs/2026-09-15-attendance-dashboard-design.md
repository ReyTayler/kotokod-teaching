# Дашборд «Посещения учеников»

Дата: 2026-09-15
Статус: утверждён, к реализации

## Задача

Отдельный экран, отвечающий на два вопроса: сколько уроков школа отработала всего
и сколько — за выбранный период, и как это раскладывается по ученикам. По клику на
ученика — детализация его уроков за тот же период.

Сейчас такой картины нет: раздел «Отчёты» умеет только фоновые Excel-выгрузки,
а вкладка «Уроки» в карточке показывает одного ученика без периода.

## Где живёт

`/admin/reports` получает две вкладки:

* **«Отчёты»** — нынешний список фоновых выгрузок, вкладка по умолчанию;
* **«Дашборд»** — список живых экранов, пока одна строка «Посещения учеников».

Строка открывает `/admin/reports/dashboard/attendance`. Существующий маршрут
`/admin/reports/:reportType` не конфликтует: у него три сегмента, у дашборда четыре.

Состояние вкладки — в `?tab=`, как в карточках ученика и группы.

Права: `IsManagerOrAdmin` на API, `manager/admin/superadmin` на фронт-маршруте —
как у всего раздела «Отчёты».

## Счётчик: что такое «отработано уроков»

Одна арифметика на весь экран — **списанные с абонемента уроки с весом**:

* занятие 45 минут = 0,5 урока, остальные = 1 (инвариант half-lesson);
* в счёт идут обычные занятия, доп.уроки и сгорания;
* бесплатные занятия (`is_free`) **не** идут: с абонемента за них не списывается.

Это ровно то, что уходит с баланса, поэтому цифра сходится с финансовыми отчётами.

Период определяется **датой занятия** (`lesson_date`), как в финансах. Доп.урок и
сгорание попадают в период по дате своего проведения, а не по дате пропуска,
который они закрывают.

## Экран

**Период.** Два поля дат (`DateInput`), по умолчанию — текущий месяц.

**Две плитки:**

* «Отработано за всё время» — по всем ученикам, от периода не зависит;
* «Отработано за период» — та же арифметика внутри выбранных дат.

Обе цифры считаются по всей школе и **не** реагируют на фильтр по имени: иначе
«отработано за период» прыгало бы при наборе букв в поиске и читалось как ошибка.

**Фильтр по имени ученика** — текстовое поле над таблицей, серверный поиск
(`ILIKE`, подстрока). Работает вместе с периодом и сортировкой, сбрасывает на
первую страницу.

**Таблица учеников.** Строка — ученик, колонки:

| Колонка | Что считает |
|---|---|
| Ученик | ФИО, ссылка на карточку |
| Обычные | занятия курса в периоде, с весом — всё, что не доп.урок, не сгорание и не бесплатное |
| Доп.уроки | `lesson_type = 'extra'` в периоде, с весом |
| Сгоревшие | `lesson_type = 'burned'` в периоде, с весом |
| Бесплатные | `is_free` в периоде, с весом |
| Итого списано | обычные + доп.уроки + сгоревшие |

«Итого» намеренно не включает бесплатные — иначе сумма разойдётся с балансами и с
плиткой за период.

Четыре типа — те же, что во вкладке «Уроки» карточки, и выводятся по тому же
правилу (`apps/students/lesson_history.py`): тип урока проверяется раньше флага
«бесплатное», потому что сгорание и доп.урок бесплатными не бывают. Две расходящиеся
классификации одного и того же факта завести нельзя — колонки перестанут сходиться
между экранами.

В списке — **все ученики, у кого есть хоть какая-то история занятий**; у кого в
периоде пусто, тот остаётся в списке с нулями (видно, кто перестал ходить).
Сортировка по умолчанию — «Итого списано» по убыванию; можно сортировать по ФИО.
Пагинация серверная, 50 строк.

**Модалка.** Клик по строке открывает детализацию уроков этого ученика за тот же
период — ту же таблицу, что во вкладке «Уроки» его карточки (номер, даты, тип,
продолжительность, группа, преподаватель, направление, «Признано»).

## Бэкенд

Два эндпоинта вместо одного: сводка не пересчитывается при листании, а список
сохраняет общий для проекта конверт `{rows, total, page, page_size}`.

```
GET /api/admin/reports/attendance-dashboard/summary?date_from&date_to
    → {all_time_lessons, period_lessons}

GET /api/admin/reports/attendance-dashboard/students
    ?date_from&date_to&page&page_size&sort_by&sort_dir&filter[full_name]
    → {rows: [{student_id, full_name, regular, extra, burned, free, billed}], ...}
```

`sort_by` — белый список (`billed`, `full_name`), `sort_dir` — `asc|desc`; мусор
даёт 400, как в списке учеников и во вкладке «Уроки». Тай-брейк — по ФИО, затем по
id, иначе страницы поедут при равных значениях.

Веса и разбивка по типам считаются одним агрегирующим запросом с условными суммами
(`SUM(...) FILTER (WHERE ...)`), без N+1 и без дозапросов на строку.

Модалке нужен период, поэтому существующий `GET /api/admin/students/:id/lessons`
получает **необязательные** `date_from` / `date_to` (фильтр по `lesson_date`).
Без них поведение прежнее — вкладка карточки показывает всю историю.

## Фронтенд

* `pages/reports/ReportsPage.tsx` — вкладки «Отчёты» / «Дашборд».
* `pages/reports/dashboards/AttendanceDashboardPage.tsx` — экран: период, плитки,
  фильтр, таблица, модалка.
* Таблица детализации выносится из `pages/students/StudentLessonsBlock.tsx` в общий
  компонент, принимающий `studentId` и необязательный период. Вкладка карточки и
  модалка получают один источник правды, а не две расходящиеся копии.
* Хуки: `useAttendanceDashboard` (сводка) и `useAttendanceDashboardStudents`
  (список) — оба с `placeholderData: keepPreviousData`.
* Даты — только `DateInput` из `components/form/`; цвета, отступы и радиусы —
  только токены из `styles/tokens.css`.

## Производительность

Замерено на боевых данных (17 293 записи посещаемости, 12 363 урока, 283 ученика):

| Запрос | Время |
|---|---|
| Цифра за всё время | 4,0 мс |
| Цифра за период | 1,4 мс |
| Список учеников, страница 50 | 11,7 мс |
| Счётчик для пагинации | 1,7 мс |
| Список с фильтром по имени | 6,7 мс |

Открытие экрана — около 19 мс работы базы, листание — 12 мс. Ни кэша, ни Celery,
ни новых индексов не требуется; при росте базы втрое счёт останется в десятках
миллисекунд. Кэшировать цифру «за всё время» незачем — она стоит 4 мс.

## Тесты

`pytest` (полный прогон из `journal_django/`, не по приложениям):

* вес половинного урока в каждой колонке и в обеих плитках;
* бесплатные занятия не попадают в «Итого списано» и в плитки, но видны в своей колонке;
* доп.урок и сгорание относятся к периоду по дате своего проведения;
* ученик без уроков в периоде остаётся в списке с нулями;
* сумма «Итого списано» по всем строкам равна плитке за период;
* фильтр по имени и сортировка: белый список, 400 на мусор, тай-брейк;
* `date_from` / `date_to` во вкладке «Уроки»: фильтруют, без них поведение прежнее;
* RBAC: менеджер видит, преподаватель — нет.
