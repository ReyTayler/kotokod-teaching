# Редизайн раздела «Продления»

Дата: 2026-08-08
Статус: утверждён, к реализации

## 1. Зачем

Раздел «Продления» — рабочий инструмент, который менеджер держит открытым весь день.
Сейчас он спроектирован как обычная страница со списком: щедрые поля, потолок
ширины, крупная шапка. Для воронки это неверная плотность — на экране помещается
мало карточек, а до данных приходится долго скроллить.

Цель: **information density first**. Это сознательное отступление от плотности,
принятой в базе знаний (там — readability first, см.
`2026-08-07-knowledge-base-redesign-design.md`). Раздел остаётся в общем
визуальном языке платформы, но живёт плотнее.

Задачи:

1. Быстро понимать состояние воронки.
2. Быстро находить конкретного ученика.
3. Быстро определять, с кем требуется действие.
4. Убрать визуальный шум.
5. Поднять плотность карточек без потери читаемости.
6. Сделать канбан удобным при большом числе колонок и карточек.

## 2. Что уже работает и не трогается

Чтобы не переделывать заново то, что уже сделано правильно:

- Лента канбана **уже** скроллится внутри себя (`.renewal-board { overflow-x: auto }`),
  горизонтального скролла `<body>` нет. Проблема не в скролле, а в двойном зажиме
  ширины (см. §3).
- Поиск в колонке — **настоящий** серверный поиск по конкретной стадии
  (`filter[student]` + `stage_id`, `apps/renewals/repository.py::column_cards`),
  а не фильтр по уже загруженным карточкам. Он не дубль глобального поиска.
- Тот же `filter[student]` работает и на уровне всей доски
  (`_board_where` применяется в `board()`), поэтому глобальный поиск не требует
  правок бэкенда.
- Сегментированный переключатель `[Канбан | Список]` уже есть (`.segmented`
  в `components.css`), активный элемент — белая плашка с тенью. Переделывать не нужно.
- Зоны закрытия сделки (drag → «Продлён»/«Ушёл»), drawer сделки, DnD-механика,
  «Показать ещё» — вне объёма этой работы.

## 3. Раскладка страницы

### Проблема

Канбан зажат дважды:

- `.app-page { max-width: var(--content-max) /* 1440px */ }` — потолок, введённый
  ради таблиц, чтобы строка из 9 колонок не растягивалась через весь монитор;
- `padding: 0 var(--page-pad-x) /* 32px */`.

Для горизонтальной ленты оба ограничения вредны: на широком мониторе видно
4–5 колонок вместо 7–8.

### Решение

```
┌─ .main (после sidebar) ────────────────────────────────────────┐
│ ┌─ .app-page (в этом разделе — без max-width) ───────────────┐ │
│ │ Продления        [Канбан|Список]  Без сделок  Аналитика ⚙ │ │  ← sticky, dense
│ │ ─────────────────────────────────────────────────────────  │ │
│ │ [🔍 Поиск ученика] [Все ответственные ▾] [Все направления ▾]│ │
│ │ Ответственный: Иванов ×   Направление: Python ×  Сбросить  │ │  ← только если есть
│ └───────────────────────────────────────────────────────────┘ │
│ ══ канбан от края до края области контента, скролл внутри ══   │
└────────────────────────────────────────────────────────────────┘
```

**Снятие потолка ширины.** В `renewals.css`:

```css
.app-page:has(> .renewals-page) { max-width: none; }
```

Правило живёт в файле раздела, ничего глобально не меняет, JS не нужен.
`:has()` поддержан во всех целевых браузерах.

**Полная ширина ленты.** Лента вырывается в поля страницы:
`margin-inline: calc(-1 * var(--page-pad-x))` + обратный `padding-inline` того же
размера. Колонки начинаются от края области контента, `overflow-x: auto` остаётся
**только** на ленте.

Величина обязана совпадать с `--page-pad-x` из `.app-page` и переключаться вместе
с ней на брейкпоинте 900px (там страница уходит на `--space-4`). Иначе лента
вылезет наружу и даст горизонтальный скролл страницы — ровно та ошибка, что уже
ловилась в `.kb-editor` (см. комментарий в `knowledge.css`).

**Вертикальный бюджет.** Экономим ≈60px до первой карточки:

- `PageHeader` получает вариант `dense`: заголовок `--fs-3xl` (20px) вместо
  `--fs-5xl` (24px), нижний отступ `--space-3` вместо `--space-4`.
  Вариант объявляется в `shell.css` — там же, где живёт сам `.page-header`.
  Раздел **не** переопределяет чужие классы у себя (владение классами,
  см. `project_design_system_audit`).
- Гэп страницы: `.renewals-page { gap: var(--space-3) }` вместо `--space-6`.

**Высота колонок.** Сейчас `max-height: calc(100vh - 220px)` — магическое число,
устаревающее при любой правке шапки. Заменяется на переменную раздела:

```css
.renewals-page {
  /* Сумма того, что стоит НАД лентой: шапка страницы (dense) + гэп +
     панель фильтров + гэп. Строка чипов в сумму не входит — она появляется
     не всегда, и колонки должны переставать тянуться, а не прыгать. */
  --rnl-board-top: <измерить при реализации>;
}
.renewal-col { max-height: calc(100vh - var(--rnl-board-top)); }
```

Точное значение снимается с собранного макета, а не подбирается на глаз;
в комментарии остаётся разбор слагаемых, чтобы следующая правка шапки не
превратила его обратно в магическое число.

## 4. Шапка раздела

```
Продления            [Канбан | Список]   Без сделок (3)   Аналитика   ⚙
```

- Сегментед `[Канбан | Список]` — как есть.
- **«Без сделок»** остаётся кнопкой, открывающей модалку (решение пользователя;
  вариант «третья вкладка» из ТЗ отклонён). Счётчик и подсветка `--warning`
  при `count > 0` сохраняются.
- **«Аналитика»** — отдельная ссылка-кнопка, вне сегментеда.
- **«Настройка стадий»** сворачивается в иконку-шестерёнку (`IconButton`)
  с `aria-label="Настройка стадий"`: текстовая кнопка занимала место ради
  действия, которое трогают раз в квартал. Права (`canWriteRenewalStages`)
  не меняются.

## 5. Панель фильтров

```
[🔍 Поиск ученика…]  [Все ответственные ▾]  [Все направления ▾]
Ответственный: Иванов ×    Направление: Python ×          Сбросить
```

**Поиск.** Компонент `SearchInput` (уже в системе), `min-width: 240px`,
`useDeferredValue` — не гоним запрос на каждый символ. Значение уходит в
`filter[student]` доски; бэкенд правок не требует. Значение живёт в URL
(`?student=`), как остальные фильтры.

В списочном виде это тот же самый фильтр — отдельное поле «Ученик» из тулбара
удаляется, его роль берёт глобальный поиск. Поле живёт в `RenewalsPage.tsx`
(тулбар раздела), а не в `RenewalList.tsx`: сама таблица списка не меняется.

**Селекты.** Uppercase-подписи над полями («ОТВЕТСТВЕННЫЙ») убираются вместе с
~20px высоты. Чтобы триггер сам себя объяснял, пустое значение переименовывается:

- `{ value: '', label: 'Все ответственные' }`
- `{ value: '', label: 'Все направления' }`

Так вариант «сбросить» остаётся доступным прямо в списке, и компонент
`SelectInput` менять не нужно.

**Чипы активных фильтров.** Отдельная строка, появляется только когда что-то
выбрано. Каждый чип — `Ответственный: Иванов` + `×` (снимает свой фильтр).
Рядом — «Сбросить» (снимает все). Чипы рисуются для всех активных фильтров
раздела, включая списочные (Цикл, Стадия, Закрытые) в списочном виде.

**Фильтр «Период» из ТЗ не реализуется.** На доске висят только *открытые* сделки
(`d.outcome_at IS NULL` в `_board_where`), у них нет даты, к которой период
применим. Период имеет смысл на закрытых сделках — он уже есть в «Аналитике»
(разбивка по месяцам).

## 6. Колонка канбана

```
┌─────────────────────────────┐  ← 3px полоса цвета стадии
│ Урок 2                33 🔍 │
│ АВТО                        │
├─────────────────────────────┤
│ карточка                    │
│ карточка                    │
└─────────────────────────────┘
```

**Ширина.** `flex: 1 0 272px` — колонки не жмутся в левый угол на широком экране
и включают скролл на узком. (Сейчас `flex: 0 0 280px`.)

**Заголовок.** Иерархия: название — главное, счётчик — вторичная метадата.

- Название: `--fs-sm`, `600`, `--text`.
- Счётчик: `--text3`, `font-variant-numeric: tabular-nums`, **без плашки** —
  число не должно превращаться в отдельный визуальный блок.
- Бейдж `АВТО` — на вторую строку, `--fs-2xs` uppercase `--text3`.
  Смысл прежний: сюда двигает только движок, вручную перетащить нельзя.

**Цвет полосы** берётся из настройки стадии (`stage.color`), как сейчас.
Системная палитра по типу стадии из ТЗ отклонена — superadmin настраивает цвета
осознанно, и ломать это ради единообразия не нужно.

**Поиск в колонке** сохраняется, но сворачивается:

- В шапке — иконка-лупа (`IconButton`).
- По клику разворачивается инпут на месте строки заголовка; Esc и `×` сворачивают.
- Если в колонке активен поиск — лупа остаётся подсвеченной (`--accent`), иначе
  свёрнутый фильтр был бы невидимым и объяснял бы «пропавшие» карточки.
- Запрос колонки **наследует** глобальные фильтры и сужает их:
  `student: colSearch.trim() || filters.student`. То есть колонночный поиск
  перекрывает глобальный только внутри своей колонки.

**Состояния колонки:**

| Состояние | Что показываем |
|---|---|
| Загрузка доски | 4 skeleton-карточки (`.skeleton-block`) в каждой колонке |
| Стадия пуста | `EmptyState`: «Нет учеников» / «На этой стадии пока никого нет» |
| Поиск без совпадений | Отдельный текст «Никого не найдено» — не путать с пустой стадией |
| Ошибка загрузки доски | `EmptyState` «Не удалось загрузить продления» + кнопка «Повторить» (`refetch`) |

Ошибка сейчас не обрабатывается вовсе: доска рендерится пустой, что читается как
«учеников нет». Это отдельный баг, чинится здесь же.

## 7. Карточка ученика

```
┌──────────────────────────────┐
│ ⬤  Имамутдинов Давид         │   14px / 600 / --text
│ Python ИНДИВ · Цикл 10       │   13px / 400 / --text3
│ Зависла 111 дн.  Долг 4 500 ₽│   11px, цвет = состояние
└──────────────────────────────┘   высота ≈ 68px
```

Целевая высота — **64–88px** в зависимости от числа бейджей.

**Имя** — главный элемент: `--fs-md` (14px), `600`, `--text`, обрезка многоточием.

**Аватар** ответственного: 28 → 22px.

**Направления** — `--fs-sm` (13px), `400`, `--text3`, **одним цветом**.
Персональный `direction.color` в тексте карточки больше не применяется: цвет в
этом разделе несёт состояние, а не название продукта. (В списочном виде чипы
направлений с их цветом остаются — там они читаются как теги таблицы, а не
конкурируют с именем.)

**Срок в стадии.** Метрика та же (`days_in_stage`), но с явной семантикой:

- `days_in_stage <= SLA_OVERDUE_DAYS` (5) → «В стадии 3 дн.», приглушённо;
- иначе → «Зависла 111 дн.» в `--danger`.

Слово «Просрочено» из ТЗ намеренно не используется: у стадии нет дедлайна, есть
порог «застряла». «Просрочено» сообщало бы о несуществующем сроке.

**Долг → величина долга.** Вместо голого слова «Долг» — `Долг 2 ур.`

Важно: баланс в этой системе измеряется **в уроках**, а не в рублях —
`balances_for_students` считает `SUM(payments.lessons_count) − посещения`
(`apps/finances/repository.py`). Drawer сделки уже показывает его так же:
«Баланс — −2 ур.». Рублёвая формулировка была бы враньём про единицу измерения.

- Бэкенд: `_annotate_debt` уже вызывает `balances_for_students` ради флага
  `debt` — добавляется `c['balance'] = float(...)`. Лишних запросов ноль.
- Фронт: поле `balance: number` в `RenewalCard` (`lib/renewals.ts`),
  форматирование — существующий `fmtLessons` (тот же, что в drawer'е,
  дробные значения через запятую: половинки уроков на 45-минутных курсах).
Три состояния баланса, разведённые по смыслу и цвету:

| Баланс | Бейдж | Цвет | Что это значит |
|---|---|---|---|
| `< 0` | `Долг 2 ур.` | `--danger` | Ученик уже занимается в минус — проглядели |
| `= 0` | `Уроки кончились` | `--warning` | Ничего не нарушено, но продлевать надо сейчас |
| `> 0` | нет бейджа | — | Запас уроков есть, действие не требуется |

Нулевой баланс — ровно тот сигнал, ради которого раздел и существует, поэтому
молчать о нём нельзя. Но и красить его в danger нельзя: свести оба состояния
в один цвет — потерять разницу между «пора работать» и «уже проглядели».

Точное сравнение `balance === 0` безопасно: баланс складывается из целых
`lessons_count` и посещений кратных 0.5, а половины представимы в двоичной
плавающей точке точно — «почти нуля» из-за погрешности не возникает.

## 8. Цвета

Литеральные HEX из ТЗ не применяются: в проекте запрет на hardcoded-цвета, и в
тёмной теме они дали бы тёмный текст на тёмном фоне. Соответствие:

| ТЗ | Токен | Значение (светлая тема) |
|---|---|---|
| Primary `#5C63FF` | `--accent` | `#4F59F9` |
| Background `#F7F8FC` | `--bg` | `#f7f9fc` |
| Card `#FFFFFF` | `--bg2` | `#ffffff` |
| Text `#1C1F2E` | `--text` | `#0f172a` |
| Secondary `#6B7280` | `--text3` | `#556274` |
| Border `#E5E7EB` | `--border` | `rgba(15,23,42,.08)` |
| Ожидание оплаты `#F59E0B` | `--warning` | `#b45309` |
| Успех `#22C55E` | `--success` | `#15803d` |
| Проблема `#EF4444` | `--danger` | `#dc2626` |

`--text3` и семантические цвета темнее оригиналов из ТЗ намеренно: подписи в
интерфейсе набраны 11–13px, а это «обычный» текст по WCAG — `#6B7280` и `#22C55E`
не проходят AA (см. комментарии в `tokens.css`).

## 10. Проверка

- Полный `pytest -q` (не по приложениям — часть приложений no-op'ит
  `django_db_setup`, прогон по частям даёт ложный результат).
- Браузерная проверка обеих тем (светлая/тёмная) на ширинах 1280 / 1600 / 1920:
  канбан во всю ширину, горизонтального скролла `<body>` нет.
- Проверка брейкпоинта 900px: лента не вылезает за край.
- Проверка состояний: загрузка (skeleton), пустая стадия, поиск без совпадений,
  сбитый бэкенд (кнопка «Повторить»).
- DnD не сломан: перенос карточки, зоны закрытия, оптимистичный апдейт счётчиков.

## 11. Вне объёма

- Третья вкладка «Без сделок» (остаётся модалкой).
- Фильтр «Период».
- Системная палитра стадий вместо настраиваемой.
- Аналитика продлений, drawer сделки, страница настройки стадий.
