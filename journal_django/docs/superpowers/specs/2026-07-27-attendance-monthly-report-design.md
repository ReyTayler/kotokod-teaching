# Отчёт по посещаемости за месяц (был/не был по каждому ученику)

Дата: 2026-07-27. Запрос руководства: сводка за месяц, где по каждому ученику
видно, был он на уроке или нет, и дата урока. Образец формы — `пример.xlsx`
в корне репозитория.

## Форма отчёта

Один лист. Каждая единица отчёта («ученик в группе») занимает **две строки**:
верхняя — даты уроков, нижняя — статусы. ФИО и группа объединены по вертикали
на обе строки (как в образце).

```
ФИО ученика | Группа      | Урок 1     | Урок 2     | Урок 3 | Итого «Был» | Итого «Не был»
Иванов Иван | Python 5-6  | 01.07.2026 | 08.07.2026 | 15.07  |      2      |       1
            |             | Был        | Не был     | Сгорел |             |
Иванов Иван | Робототех.  | 02.07.2026 | 09.07.2026 |   -    |      2      |       0
            |             | Был        | Был        |   -    |             |
Сидоров Пётр| —           |    -       |    -       |   -    |      0      |       0
            |             |    -       |    -       |   -    |             |
```

Колонки «Урок N» — **порядковые уроки самого ученика** внутри месяца, а не
календарные даты и не номера уроков курса. У разных учеников в одной и той же
колонке стоят разные даты. Число колонок = максимум уроков у самой активной
пары ученик×группа за месяц.

## Статус ячейки

Доп.урок (отработка) и сгорание материализуются в БД как **настоящие
записи-уроки** (`lessons.lesson_type = 'extra' / 'burned'` + строка в
`lesson_attendance`), связанные с пропуском через `AbsenceResolution`
(см. `apps/extra_lessons/`).

**Главное правило: отработка и сгорание НЕ создают лишнюю колонку — они
«ложатся» на позицию своего пропуска, меняя её статус.** Иначе отчёт читается
так, будто ученика не было на уроке 2 и он был на уроке 3, хотя на деле он
отработал именно за урок 2 (решение 2026-07-27 после разбора реального случая:
Андреев Михаил, пропуск и отработка 19.07 в один день).

| Условие | Ячейка |
| --- | --- |
| `present = true` (в т.ч. `is_free`) | `Был` |
| пропуск, отработан в ЭТОМ месяце | `Отработал` |
| пропуск, сожжён в ЭТОМ месяце | `Сгорел` |
| пропуск без решения (или решённый в другом месяце) | `Не был` |
| доп.урок/сгорание за пропуск ДРУГОГО месяца | `Отработка за 14.06.2026` / `Сгорел (за 06.02.2026)` |
| доп.урок СВЕРХ курса (`kind='extra'`, пропуска нет) | `Доп.урок` |
| в этой позиции у пары ученик×группа урока нет | `-` |

### Разные месяцы

Пропуск и его закрытие сплошь и рядом в разных месяцах (в боевых данных:
пропуск 14.06 → отработка 19.07; пропуск 06.02 → сгорание 23.07). Ложиться
тогда не на что, поэтому факт показывается **своей колонкой с пояснением, за
какой день он закрыт**.

Обратная сторона того же правила: ячейка пропуска меняет статус, только если
закрытие произошло **внутри того же месяца**. Пропуск июля, отработанный в
августе, в июльском отчёте остаётся `Не был`, а в августовском появится как
`Отработка за 19.07.2026`. Так каждое событие попадает ровно в один месячный
отчёт и не задваивается между соседними.

### Итоговые колонки

`Итого «Был»` / `Итого «Не был»` / `Итого «Отработано»` — по категории ячейки
(`kind`), а не по её подписи: подпись бывает динамической. `Доп.урок` считается
присутствием. `Сгорел` не входит ни в один счётчик — это не посещение и не
пропуск, а закрытие пропуска сжиганием.

### 45-минутные занятия — считаем ЗАНЯТИЯ, а не уроки

Каждая запись журнала = одна колонка, независимо от длительности. У 45-минутной
группы, отводящей два занятия подряд, выходят две колонки с одной датой (в
боевых данных: Афонин Иван, 24.07.2026, уроки курса №37.5 и №38) и итог
`Был = 2`.

Half-lesson (`45 мин → 0.5 урока`) здесь **намеренно НЕ применяется**, хотя
бухотчёт и прогресс курса те же два занятия считают за 1 урок. Решение
пользователя от 2026-07-27: отчёт отвечает на вопрос «сколько раз пришёл /
не пришёл», а не «сколько уроков курса отработано», и целые числа важнее
совпадения с бухгалтерией. Расхождение вдвое у 45-минутных групп — известное и
принятое, чинить его «заодно» нельзя.

Колонки при этом не схлопываются: два занятия — две независимые записи, у них
могут быть разные статусы (был на первом, не был на втором), и схлопывание
потеряло бы один из них.

## Охват строк

**Все ученики базы** (сейчас 286), включая тех, у кого в этом месяце уроков не
было вообще.

Набор групп для ученика = объединение:
* групп, в которых у него были уроки в этом месяце, и
* его активных членств (`group_memberships.active = true`).

Так группа, которая в этом месяце не занималась, тоже видна — строкой сплошных
`-`, а не молча пропадает. Ученик без уроков и без активных членств даёт одну
строку с прочерком в колонке «Группа».

Сортировка: по ФИО, внутри ученика — по названию группы, уроки — по дате
(при совпадении дат — по `lesson_number`, затем по `lesson_id`).

## Архитектура

Точная калька с бухгалтерского отчёта (`apps/finances/reports.py` +
`apps/reports/builders/accounting.py`): доменная логика живёт в своём
приложении, раздел «Отчёты» подключает её тонкой обёрткой.

| Слой | Файл | Ответственность |
| --- | --- | --- |
| Сбор + рендер | `apps/lessons/attendance_report.py` | `collect_month(month)`, `build_workbook(rows)`, `write_xlsx(rows, path)`, `render_bytes(rows)` |
| CLI (шаг 1) | `apps/lessons/management/commands/export_attendance_report.py` | `--month=YYYY-MM [--out=path.xlsx]` |
| Раздел «Отчёты» (шаг 2) | `apps/reports/builders/attendance.py` + `ReportType.ATTENDANCE_MONTH` | обёртка `build(month) -> (bytes, rows, filename)` |

### Запросы

Ровно четыре запроса, без N+1 и без запросов в цикле:

1. посещения за месяц — `LessonAttendance` c join-полями через `.values()`
   (ученик, группа, дата, `lesson_type`, `present`);
2. резолюции, задевающие месяц (`fact_lesson` ИЛИ `missed_lesson` внутри месяца)
   — два словаря по ключу `(lesson_id, student_id)`: «этот урок — факт» и
   «на этом уроке пропуск»;
3. все ученики — `Student.objects.order_by('full_name').values('id', 'full_name')`;
4. активные членства — `GroupMembership.objects.filter(active=True)`.

Сборка строк — в Python. Объём: ~500 посещений и 286 учеников на месяц,
доли секунды; отдельный кэш не нужен.

`month` валидируется через `msk_month_range(f'{month}-01')` — тот же путь, что
у бухотчёта, `ValueError` при кривом формате.

Покрыть:

  (лишней колонки нет, порядок уроков не сдвигается);
* отработка/сгорание за пропуск другого месяца — своя колонка с пояснением,
  при этом в отчёте месяца пропуска ячейка остаётся `Не был`;

* `is_free` → `Был`, `unpaid_skip` → `Не был`;
* ученик без уроков в месяце попадает в отчёт строкой прочерков;
* граница месяца: урок 30.06 и 01.08 не попадают в отчёт за июль;
* итоговые счётчики (`Сгорел` не входит ни в один);
* рендер: xlsx открывается openpyxl, объединения A/B на паре строк, число
  колонок = максимуму уроков.
